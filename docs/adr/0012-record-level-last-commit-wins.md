# ADR-0012: DB全体ではなく変更項目ごとの後勝ちにする

日付：2026-11-03  
状態：採用

## 決定と理由

DB全体のスナップショットを最後に保存したタブで上書きする方式にはせず、食事レコード・食品ID・設定項目などの変更差分を保存確定順に適用する。

別タブで別々の食事を編集しただけなのに、片方の古いスナップショットで無関係な記録まで消してしまうため。同じ記録への競合は利用者の希望どおり後の保存を採用し、再描画・再計算とトーストで知らせる。

端末の時計の前後では順序を決めず、保存トランザクションの単調増加する版を使う。

## 引き受ける不利益

同じレコードで別フィールドを同時編集した場合も、レコード単位で後の値を採用する。全ての意図を自動マージする方式ではない。全体復元は通常の差分競合とは分けて扱う。

## 見直す条件

オンライン同期へ進み、複数端末・オフライン編集の競合を扱う段階。現在のローカルDBの保存順だけではその順序を決められない。
