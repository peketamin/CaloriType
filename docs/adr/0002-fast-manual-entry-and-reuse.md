# ADR-0002: 手入力の速さと前回値の再利用を中心にする

日付：2026-11-03  
状態：採用（会話で合意した方針。未決事項は採用に含めない）  
関連：[デザインドック](../design.md) / [ADR一覧](README.md)

## 背景

料理名を一覧から選んだ標準値だけでは、実際に食べた量に合わない。手入力ですばやく記録し、次回の同じ料理で設定を繰り返さずに済ませたい。

## 検討した選択肢

- 料理一覧の標準値をそのまま使う。
- 材料と出来上がり重量を積み上げるレシピ方式。
- 1食分の登録、量の修正、前回の入力の補完を組み合わせる。

## 決定

部分一致の候補とカロリー補完を使い、入力確定前に量を修正する。グラム・個数に対応し、自作の食品・料理を再利用できるようにする。

初版ではカレーを「1食分」として登録すればよく、材料を積み上げるレシピ機能は入れない。次回カレーを入力する際には前回カロリーを引き継いで補完する。

主な場面は自炊だが、外食モードのカロリー上乗せ補正も支援する。減量・維持・筋トレを利用対象から除外しない。

## 理由と影響

登録に必要な手間を抑え、いつもの食事を繰り返し記録しやすくする。標準値への固定やレシピの作り込みを必須にしない。

推定値であること、基準量と単位を示す必要がある。食品データの出典や許諾を確認する。前回値と保存済み食事を分け、過去を勝手に更新しないスナップショット方式を設計案とする。

## 未決事項

候補順序、文字入力・IME・確定キー、前回値の記憶単位、編集で記憶を更新するか、分数操作した量の再利用、外食補正の量・固定値/割合・二重適用防止。外食モードの詳細はまだ合意済みではない。
