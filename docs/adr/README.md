# ADR — あとから失われやすい判断理由

更新日：2026-11-03

## 記録する条件

「AにはせずBにする。なぜなら〜だからだ」と説明する必要がある重要な判断だけを残す。

- 選べる代替案があり、退けた理由が後から仕様だけでは読み取れない。
- その理由が実装・運用・将来の変更に影響する。
- 採用した判断である。調査中の案は技術調査または未決事項に置く。

通常の機能追加、ボタンの値、表示方法、設定の初期値、単なる採用チェックのためには作らない。PRDや技術設計にある仕様をADRへ重複転記しない。

各ADRは「決定と理由」「引き受ける不利益」「見直す条件」を短く記す。少人数の運用に合わせてテンプレートを最小にする。参考：[ADRの趣旨](https://adr.github.io/)。
