# ADR-0011: PFC自動推測を食品データ検索と軽量モデルで構成する案

日付：2026-11-03  
状態：提案（未採用）  
関連：[デザインドック](../design.md) / [決定状況](../open-decisions.md) / [ADR一覧](README.md)

## 背景

食品名・料理名からPFCを自動推測したい。ネットワークなしでも使えるモデル、バッチ処理、独自学習の必要性を検討する。

## 確定している要件

PFCの自動推測、頻出食品の初期登録、利用者による編集、前回値の再利用、入力の速さ。特定のモデルや独自学習は未採用。

## 選択肢

1. 食品データと名前・別名の検索で自動補完する。
2. 既存の埋め込みモデルで近い食品を検索し、その基準値から補完する。
3. 独自の栄養値回帰モデルを教師データから学習する。
4. ローカルの生成モデルに数値を出力させる。

## おすすめ

最初は1を実装・評価し、不足する表現の対応へ2を追加する。独自学習は、既存方式の評価不足と信頼できる教師データが明確になった場合に検討する。

Python/Sentence Transformersで食品の検索ベクトルをバッチ作成し、ONNXモデルと索引をブラウザで使う構成を候補とする。Transformers.js / ONNX Runtime Web、multilingual-e5-smallは比較対象であり、採用・検証済みではない。

## 影響と採用条件

推定値には根拠食品と基準量を持たせる。類似度を正解確率とみなさず、同名料理の実際の材料や量が確定したかのように扱わない。候補が不十分なら不明とする。

モデル取得・キャッシュ・Web Worker・実行環境の差を評価し、入力や手修正を待たせない。語彙検索と意味検索の遅延目標は区別する。

詳細と一次資料は[技術調査](../offline-pfc.md)へ記載した。精度・容量・端末遅延・配布条件を確認してから採用へ変更する。
