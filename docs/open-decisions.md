## 優先順位

- 「先」：入力・保存の実装前か操作モックで決める。
- 「統計前」：自動目標・統計の実装前に決める。
- 「公開前」：実データでの運用や正式公開の前に決める。
- 「後続」：同期・iOSの各フェーズ開始前に決める。

最初はD01（高速入力）、D02（記憶）、D04（外食補正）を操作モックで比較する案。計算式や保存方式などの実装判断は根拠と検証結果を含めてADRへ採用する。

## 詳細

<a id="d01"></a>

### D01：入力の確定操作・候補順

決定時期：先。状態：未決。

**おすすめ**：Enterはまず候補選択、量の調整後にもう一度Enterで保存。IME変換中は保存しない。候補は名前の一致を優先し、その中で最近使ったものを上へ。スマホでは保存ボタンも常時押せるようにする。

**補足・残る判断**：1件の入力完了時間と操作数をモックで計測し、誤確定率と一緒に評価する。

<a id="d02"></a>

### D02：前回値の記憶単位・更新契機

決定時期：先。状態：未決。

**おすすめ**：食品ごとに前回確定した量・単位・カロリー・PFCをまとめて補完する。入力中やキャンセルでは更新しない。前回の半量をそのまま再現できる一方、初期の基準量に戻す操作も残す。過去の記録はスナップショットとして固定する。

**補足・残る判断**：過去の食事の編集を前回値の学習に使うかは別途確認。自炊と外食の記憶は混同しない。

<a id="d03"></a>

### D03：食品データ・自由入力・単位換算

決定時期：先。状態：未決。

**おすすめ**：利用者が登録した食品と前回値を優先し、基準量・単位・出典を明示する。共有の食品データは出典と利用条件を調査してから採用する。個数と重量は食品ごとの換算値がある場合のみ変換する。

**補足・残る判断**：名前だけから栄養値や1個の重量を断定しない。カロリーだけでも記録可能にし、PFCは不明として保持する。

<a id="d04"></a>

### D04：外食の上乗せ方法

決定時期：先。状態：未決。

**おすすめ**：外食モードでカロリー上乗せボタンと補正量を表示し、量は利用者が選べるようにする。一律の推定割合を事実として自動加算しない。補正は元の値と分けて持ち、切り替えのたびに重複加算しない。

**補足・残る判断**：前回の外食記録を再利用した場合は前回補正込みであることを示す。最初の候補量・割合対応・PFCの比例変更の表示をモックで確認する。

<a id="d05"></a>

### D05：PFC・0値・端数

決定時期：先。状態：未決。

**おすすめ**：PFC割合は4/9/4換算のエネルギー比率を候補とする。カロリーとPFCの表示は不一致を許容し、推定/不明を明示。PFCの個別編集を可能にし、不明を0と同一にしない。内部精度を保持し、kcalは整数、gは小数1桁で表示する。

**補足・残る判断**：負値になる減算は0で止める。0から加算してもPFCを捏造せず、基準値があればそれを使い、なければ不明とする。式と表示ルールは実装前に確認する。

<a id="d06"></a>

### D06：日付境界・タイムゾーン

決定時期：先。状態：未決。

**おすすめ**：終了境界は当日20:00〜翌06:00を15分単位で調整する案。実際の日時と所属日を分け、隣接日の開始は前日の終了境界と一致させる。境界変更で移る食事を確定前に表示する。

**補足・残る判断**：二重計上・空白期間を禁止。タイムゾーンは初回の設定を維持し、旅行時に自動で過去を組み替えない案。範囲とタイムゾーン切り替えの詳細は要確認。

<a id="d07"></a>

### D07：タイムラインの縮尺・移動

決定時期：先。状態：未決。

**おすすめ**：時間軸は時刻に比例させ、食事ブロックには読める最小高さを確保する。同時刻の複数アイテムは同じブロックにまとめる。ドラッグ以外に編集画面の移動先選択を用意する。

**補足・残る判断**：ブロック間の移動は複製せず所属を変更する。移動で時刻も変えるか、日をまたぐ移動を許すかはモックで確認する。

<a id="d08"></a>

### D08：ブロック変更・削除

決定時期：先。状態：未決。

**おすすめ**：安定IDを使い、表示名や色の変更で既存記録を壊さない。既存記録を持つブロックはアーカイブでき、過去の表示名を保持する。削除する場合は移動先を指定する。

**補足・残る判断**：初版ではブロック名・色・順序・追加/アーカイブの範囲を優先する案。記録そのものを連動削除しない。

<a id="d09"></a>

### D09：目標の計算式・入力条件・体重

決定時期：統計前。状態：未決。

**おすすめ**：計算式と活動係数は根拠・対象範囲を確認した別ADRで確定する。利用者が提案理由と前提を見て編集できるようにする。目標体重の到達日を入力し、目標には適用開始日を持たせる。

**補足・残る判断**：初版の体重は目標算出に必要な値を中心とし、体重推移グラフは後回し。PFCの個別目標は追加候補。自動提案の式・上下限は今回決定しない。

<a id="d10"></a>

### D10：完了後の編集

決定時期：統計前。状態：未決。

**おすすめ**：完了ボタンを明示し、完了後に食事を追加・変更・削除した日は入力途中へ戻す。再び完了にすると統計へ反映する。

**補足・残る判断**：うっかり不完全な記録が長期予算へ入ることを防ぐ。完了を取り消したことと統計の対象日数を表示する。

<a id="d11"></a>

### D11：今日・部分週・上位期間の差分

決定時期：統計前。状態：未決。

**おすすめ**：長期の調整先は翌日から期限までとし、今日の残りはホームで別計算する。残り0日は調整量を出さず期間の差分だけ表示する。週表示は1日あたりの調整量×7とし、残り日数も併記する。

**補足・残る判断**：月のカードから四半期末へ調整する場合は四半期開始からの完了日差分を1回だけ集計し、他カードの差分を重ねて足さない。未来に目標変更がある場合は適用日ごとの目標で予算を合計する。

<a id="d12"></a>

### D12：取り消し範囲・保持期間

決定時期：先。状態：未決。

**おすすめ**：食事の追加/編集/削除/移動、日付の区切り、ブロック設定、目標設定を一操作単位で取り消せるようにする。初版は現在の利用セッション内の直近100操作を候補とする。

**補足・残る判断**：新しい編集でやり直し履歴は破棄。再起動後の履歴は後回し。JSON復元は履歴へ混ぜず、復元前バックアップで戻せるようにする。

<a id="d13"></a>

### D13：保存方式・スキーマ

決定時期：先。状態：未決。

**おすすめ**：ブラウザではIndexedDBを第一候補とし、安定ID・日付インデックス・スキーマ版を持つ。日付単位に読み出し、全履歴の毎回書き換えを避ける。

**補足・残る判断**：技術選定は採用するUI方式と合わせてADR化する。保存失敗を保存済みとして扱わず、再試行と書き出しを用意する。

<a id="d14"></a>

### D14：JSON復元・移行

決定時期：先。状態：未決。

**おすすめ**：初版の復元は全体置き換えに絞る。事前検証と件数プレビュー、復元前バックアップを行い、記録・食品・設定・目標履歴をまとめて戻す。

**補足・残る判断**：失敗した復元は適用しない。重複排除や端末データとのマージは後続。古いスキーマは対応版だけ移行し、未知の新しい版を勝手に解釈しない。

<a id="d15"></a>

### D15：性能の数値目標・対応端末

決定時期：先。状態：未決。

**おすすめ**：入力候補は操作から表示まで100ms以内、保存から画面反映は200ms以内を初期の測定目標案にする。10万件を蓄積した状態でも確認する。

**補足・残る判断**：実測済みの保証ではない。対象のiPhone SafariとPCブラウザ・端末・測定条件を先に決め、p95などの評価基準を確定する。検索・日付インデックス、集計キャッシュと表示範囲の読み込みを評価する。

<a id="d16"></a>

### D16：アクセシビリティ・チュートリアル

決定時期：先。状態：未決。

**おすすめ**：色以外にも数値とラベルで超過を伝え、キーボードとスクリーンリーダーで記録・修正できる設計にする。チュートリアルは短い段階表示とし、スキップ・再表示を可能にする。

**補足・残る判断**：IME、フォーカス復帰、ドラッグ代替、文字拡大、動きを減らす設定を受け入れ条件へ含める。

<a id="d17"></a>

### D17：PWA・外部解析・バックアップ案内

決定時期：公開前。状態：未決。

**おすすめ**：記録を妨げないWebをまず完成させ、PWA・オフラインの保証範囲は次の段階で決める。初版は外部解析を入れず、JSONバックアップを案内する。

**補足・残る判断**：端末内保存が消去・紛失への保証ではないことを説明する。実データを使う前に保存先と書き出しを理解できるようにする。

<a id="d18"></a>

### D18：オンライン同期・iOS

決定時期：後続。状態：未決。

**おすすめ**：認証・所有者ごとの認可、安定IDと版、競合、削除の伝播、通信と保管、復旧を同期着手前に独立して設計する。iOS方式とWebとの共有範囲はWebの操作検証後に決める。

**補足・残る判断**：同期・iOSは確定済み技術として扱わない。健康情報を含む実記録はコード用GitHubリポジトリに保存しない。

<a id="d19"></a>

### D19：商標・ドメイン・運用・課金

決定時期：公開前。状態：未決。

**おすすめ**：正式公開前に称呼を含む商標確認とドメイン調査を行い、公開範囲・問い合わせ先・データの扱いを決める。初版の価値検証中は広告・課金設計を後回しにする。

**補足・残る判断**：名前のWeb検索でヒットしないことと、商標の利用可否は区別する。記録の所要時間・操作数・翌日の継続・復元成功を検証し、数値目標は観察後に確定する。

<a id="d20"></a>

### D20：偉人の言葉のランダム表示

決定時期：モックで確認。状態：未決。

**おすすめ**：ホーム下部に小さな「今日の言葉」を置く。1日1回ランダムに選び、その日は固定。「別の言葉」で切り替え可能、設定で非表示にもできる。入力中に差し込むモーダルや通知にはしない。

**補足・残る判断**：初版は出典と利用条件を確認した20〜30件程度を同梱する案。著者・作品・出典リンクを表示し、翻訳者や権利確認の情報も保持する。誤帰属・創作を偉人の引用として表示しない。継続・習慣・節制を中心に、超過を責めるイベントには連動させない。

## 決定の残し方

利用者の回答や操作検証で採用した案は、デザインドックと該当ADRを更新し、本一覧を採用済みとして更新する。採用前におすすめを実装確定事項として扱わない。
