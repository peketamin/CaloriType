# 仕様監査：現在の実装と残件

更新日：2026-11-03  
状態：今回の追加仕様を反映。実機・本番品質・無制限件数を保証するものではない。  
関連：[PRD](design.md) / [保存・2年窓・競合](data-window-and-conflicts.md) / [目標変更](goal-changes.md)

## 今回解消した差

- デモ/記録の分離を維持したまま、IndexedDB v2へ移行。
- 過去は当時の目標で比較し、適用日を持つ目標変更と予算再計算ボタンを追加。
- 詳細集計は直近2年。古い原本は保持し、範囲付き年次キャッシュへ集約。
- 年途中の境界による二重計上、過去編集後の年次キャッシュの陳腐化に対応。
- 履歴は差分で保持し、全履歴/全DBの毎回コピーを廃止。
- レコード/項目単位の後勝ち、別タブへの通知、再描画・再計算。
- 保存失敗の差分をJSONへ退避し、保存を再試行。
- 食事区分の指定・移動で開始時刻を補正し、現在時指定も追加。
- プロンプトではない食品編集画面、新規食品の登録。
- 未知のPFCをカロリーと仮の比率から推定する2点スライダー。2.5ポイント刻み。
- 引用に英訳を併記し、本アプリによる訳と明示。
- 明示的な0 kcal完了日、旧DB移行、不正な復元ファイルの検証。

## 2年窓の整理で必要な例外

古い原本を保持して後から修正できる以上、古い年の再構築を完全禁止すると不整合になる。通常の統計は2年に限定し、古いデータを読むのは原本閲覧・該当年の訂正・移行/復元/修復・全体書き出しとする。

年次キャッシュは原本の代わりではなく、集計範囲を持つ派生データ。年途中の境界年を丸1年の合計として足さない。

## 公開とデータ

Pagesで公開するのはmockup/のコードと同梱データだけ。記録をリポジトリへ自動送信しない。SitesからPagesへブラウザ保存は共有されない。

モード分離は誤操作防止であり、同一オリジンの別スクリプトから健康情報を保護する境界ではない。端末・ブラウザ消去に備えてバックアップを持つ。

GitHub側の公開状態とPages設定はデプロイ結果で確認する。公開前でも検証結果や未実装範囲を誤って本番品質として扱わない。
