# 仕様監査：現モックとの差と未決事項

更新日：2026-11-03  
状態：現実装と合意した要件の差分。提案を自動的に採用扱いしない。  
関連：[PRD](design.md) / [目標変更の計算](goal-changes.md) / [Pages公開手順](../mockup/PUBLISHING.md)

## 今回対応したこと

- デモと記録（試用）の保存キー・操作履歴・バックアップのモードを分ける。
- デモのリセットが記録モードを変更しない。
- 記録モードの初期値は空の食事・未設定の目標/体重とし、サンプルを本人の実績にしない。
- モードをまたぐJSONの誤復元/食品上書きを拒否する。旧モックのモードなしファイルはデモ用として扱う。
- 未登録食品の仮の100 kcalを廃止し、本人の入力を必須にする。
- 未登録食品の保存時に必要な別名フィールドを補い、再読み込み時の検証失敗を直す。
- 明示的に記録完了とした0 kcal日を、未記録と区別して長期差分へ含める。
- GitHub Pagesの /CaloriType/ 配下で相対パスの資産を読み込む。

## 実用版の前に解消する差

| 優先度 | 差・破綻の可能性 | 対応 |
| --- | --- | --- |
| 高 | 現在の目標で過去も比較しており、目標変更履歴の要件を満たさない | 日付ごとの目標版で再集計。[必要な決定](goal-changes.md) |
| 高 | 全履歴走査と状態全体のUndoスナップショットは、10万件×1000操作へ拡張できない | 日付索引、増分集計、差分履歴へ変更し対象端末で検証 |
| 高 | 食品値は操作用の参考値で、全データの出典・正誤・基準量を精査していない | 配布用食品マスターを別に整備し、版と出典を持つ |
| 高 | 複数タブで同じモードを編集した場合の競合を検出していない | 更新版の確認・排他/競合通知を設計。今の試用は1タブを基本とする |
| 中 | 食事ブロック間の移動で時刻を保持すると、夕食なのに08:00になる場合がある | 「時刻を保持/移動先へ合わせる」の意味と確認UIを決める |
| 中 | カードは時刻ラベル付きの縦並びで、完全な時間比例スケールではない | 最小高さと時間軸の関係、重複表示を実装・検証 |
| 中 | 食事ブロックは名前変更のみで、追加・アーカイブ・移動先付き削除は未実装 | 設定画面を具体化 |
| 中 | 修復は基本診断と画面再集計まで。原本破損や途中移行を救出する仕組みは未実装 | 原本退避と派生索引の再構築、隔離の具体化 |
| 中 | 自動目標算出、意味検索モデルによるPFC推測は未実装 | 先に算術/語彙検索と推定式/モデルを分けて評価 |
| 中 | 全体バックアップと食品用ファイルは独自スキーマ。多様な外部形式は読めない | 仕様を固定し、版・必須項目・上書き範囲を明記 |

## 継続して決めること

- 外食率の初期値・範囲。モックは0%、−90〜200%であり、本番の決定ではない。
- PFC不明時の推測基準、量の換算、表示カロリーと4/9/4換算のずれ。
- 目標の適用日・持ち越し・推定式・再計算時の確認・調整幅。
- 食品インポートの照合ID、削除の扱い、配布版更新と本人編集の衝突。
- 初回公開の必須範囲、対象端末・ブラウザ・性能指標、継続の成功基準。
- 商標、ドメイン、引用集、公開範囲、バックアップ頻度と問い合わせ先。

## Pages公開での境界

GitHub Pagesではアプリのコードと同梱データを公開する。ブラウザの記録は自動でリポジトリへ送信しない。公開サイトであることと、健康情報を公開することは別である。

SitesとGitHub Pagesは異なるオリジンなのでIndexedDBは共有されない。既存の記録は書き出し・読み込みが必要で、勝手にコピーしない。モードの分離は誤操作防止であり、同一オリジンの別アプリに対するセキュリティ境界ではない。

現モックの保存や修復を本番品質・無制限性能の検証済みとして公開しない。記録側の表示も「試用」とする。
