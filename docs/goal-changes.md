# 途中の目標変更と自動計算：決めること

更新日：2026-11-03  
状態：整理とおすすめ。既存の合意以外の初期値・式・適用ルールは未採用。  
関連：[PRD](design.md) / [仕様監査](spec-audit.md) / [技術設計](technical-design.md)

## 2種類の自動計算を分ける

1. 身体条件・活動量・目標体重・目標日から、新しい1日あたりの目標を提案する。
2. 決まった日次目標の履歴と実際の記録から、期間の残り予算と調整量を再集計する。

2はカロリー予算の算術であり、1の生理的な推定式が決まらなくても実装できる。1の精度と2の整合性を混同しない。現在のモックは2にも未対応で、現在の目標で過去を比較している。

## すでに合意したこと

- 目標は自動提案を編集できる。
- 初版は活動量設定を使い、個別運動のカロリーを自動加算しない。
- 目標変更には適用日を持たせ、過去は当時の目標で評価する。
- 長期差分には完了日だけを使う。
- 調整先は翌日以降。暦の週・月・四半期・半年・年で扱う。
- 過去の食品や目標の変更で、記録と評価を無操作で変えない。

## 実装前に指定するルール

| 論点 | おすすめ | 状態 |
| --- | --- | --- |
| 新目標の適用日 | 通常は翌日から。今日からにする場合は、その日全体の目標が変わることを確認して選べる | 未採用の提案 |
| 過去の訂正 | 通常の目標変更と分ける。遡及訂正は対象日・再集計結果を確認して明示的に実行 | 未採用の提案 |
| 過去の超過/不足 | 目標変更だけでは消さず、その日の旧目標との差分を引き継ぐ。リセットは別操作にする | 詳細案。持ち越し方は要確認 |
| 自動提案の入力 | 計算基準日の体重・身長・年齢・式に必要な身体条件・活動量・目標体重・目標日を保存 | 入力方針は合意、必須属性・式は未確定 |
| 再計算のきっかけ | 体重や活動量などが変わると再提案し、利用者が確認するまで確定目標を変えない | 未採用の提案 |
| 残り期間 | 新提案の日から目標日までの日数を使う。維持・増量・減量で目標日が不要/不適切な場合を定義 | 用途の方針は合意、詳細は未決 |
| 生理的な推定式 | 計算式・係数・対象範囲・提案の上下限を根拠確認して決める | 未決。現在は式を採用しない |
| 将来の目標 | 適用開始日順の版を保持し、次の変更まで継続。予定された変更も日ごとに予算へ反映 | 未採用の詳細案 |
| 調整の上限 | 巨大な差分を短期間で必ず相殺させない。調整可能幅・残す差分・表示を定義 | 未決。数値上限は要検討 |
| 日付・丸め | 設定済みタイムゾーンと論理日付で適用。内部精度を保持し表示時に丸める | 基本方針は合意、端点の詳細は未決 |

## 期間予算の例

月〜水の目標は2000 kcal/日、完了した3日間の実績合計は6300 kcalだったとする。木曜から1800 kcal/日へ変更し、日曜まで4日残っている場合：

- 過去の超過：6300 − (2000 × 3) = 300 kcal
- 将来の目標予算：1800 × 4 = 7200 kcal
- 差分調整後の残り予算：7200 − 300 = 6900 kcal
- 1日あたりの目標からの調整：−300 ÷ 4 = −75 kcal/日

算術上は1725 kcal/日相当になる。これは計算の説明例であり、個人の適切な摂取量の提案ではない。実際に提示する値には、別途決める調整の適用条件を反映する。

旧目標まで1800へ書き換えて6300 − 5400 = 900 kcal超過とすると、過去の評価を改変してしまう。その計算はしない。

## データの具体化案

GoalVersion：
- 安定ID、作成日時、適用する論理日付、タイムゾーン。
- 入力条件のスナップショット、計算式と係数の版。
- 自動提案値、本人が確定した値、手動変更の有無。

期間集計：
- 完了日dの実績I(d)と、その日有効だった目標T(d)の差分を合計。
- 調整先の各日にも、その日有効になる予定目標を適用して合計。
- 完了していない日は差分へ入れない。明示的な完了0 kcal日は対象に含める。
- 期間末の残り0日では割り算をせず、差分だけを表示する。

適用開始日と日次目標の履歴を先に実装し、身体条件からの推定式は独立して追加する進め方をおすすめする。式や上限が決まるまで、暗黙の7700 kcal換算などを自動提案の正解として実装しない。
