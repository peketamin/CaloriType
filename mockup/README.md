# CaloriType 操作版

GitHub Pagesで公開する静的アプリです。データはブラウザのIndexedDBに保存し、デモ/記録（試用）を分離します。[公開手順](PUBLISHING.md)。

## 操作できること

- 名前/前回値の補完、量・分数・kcalの調整、外食補正。
- 食事区分を指定/移動すると開始時刻に補正。「現在時を指定」では現在の日時と対応区分を選ぶ。
- 開始時刻は設定で変更。範囲は次の区分の開始まで。
- 食品一覧から専用画面で名称・別名・基準量/単位・重量・kcal・PFCを編集、新規登録。
- PFC不明ならカロリーから仮置き。2点のスライダーでP/F/Cを2.5ポイント刻みに調整。P/Fラベルで操作するつまみを選択可能。
- 目標の適用日、変更後の予算再計算、日付ごとの目標履歴。
- セッション内の差分Undo/Redo（デフォルト1000、設定可能）。
- タブ間は変更レコード/項目ごとに保存確定順で後勝ち。通知後に再描画・再計算してトーストを表示。
- 直近2年を通常集計し、古い原本は保持。古い日付の履歴表示と範囲付き年次キャッシュ。
- 全体JSONのバックアップ/復元、食品用JSON、Markdown。保存失敗の差分もJSONへ退避し再試行。
- タイムラインの「Markdownでコピー」で、表示中の1日分を食事区分ごとの小計と食品名・kcalだけのリストとしてコピー。空の区分は省略し、日付境界も反映。自動コピー不可の場合は手動コピー画面を開く。
- 原本退避・日付索引と年次キャッシュの再構築。
- チュートリアル、原文＋本アプリによる英訳の日替わりの言葉。

## 起動

リポジトリのルートから：
```sh
python3 -m http.server 8080 --directory mockup
```
http://localhost:8080 を開きます。保存にはHTTPSまたはlocalhostを使ってください。

## テスト

ビルドにnpm依存は不要。npmは開発用ブラウザテストだけに使います。

```sh
npm ci
npx playwright install chromium
npm test
npm run test:performance
```

テストランナーが /CaloriType/ 配下を模したローカルサーバーを起動します。インストール済みChromiumを使う場合はCHROMIUM_PATHで実行ファイルを指定できます。テストは人工データだけを使い、利用者の記録へ接続しません。

## 留保

「記録モード（試用）」は、デモとは別に本人の記録を保存できる一方、本番品質の確認が未完了であることを表す。保存が毎回リセットされるモードではない。実機Safari・継続運用などの検証は残っている。

参考食品値の精査、身体条件からの日次目標の自動提案、意味検索モデル、完全な時間比例スケール、ブロック追加/アーカイブ、固定タイムゾーンでの旅行対応、原本が失われた場合の救出は未完了です。

目標の「再計算」は手動で入力した日次目標と履歴による予算の再計算です。身体条件からの自動推定とは区別します。PFCの15/25/60は仮置きの初期値で、食材の実測値や推奨摂取比率ではありません。

旧版の目標履歴が無いデータは移行時の暫定値を明記します。モードなし旧ファイルはデモ用として扱い、記録側へ勝手にコピーしません。
